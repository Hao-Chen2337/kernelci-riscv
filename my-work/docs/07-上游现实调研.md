✅ **时间线紧急且判断正确**:#49 最新评论 08-24,21 天红线 = **09-14(剩 ~6 天)**;[#579](https://github.com/kernelci/kernelci-project/issues/579)(xjysiiau 开)零回应,社区对 RISC-V pull-lab 静默。**回帖 + 开 tracking issue(kernelci/kernelci-project,勿开在 pipeline)是正确且第一优先的动作。**

### 计划需要修正的点(按优先级)

1. **⚠️ 删掉/改写 PR1 描述里的"结果回收待上游接线"**。线上有 1983 条 pass,maintainer 扫一眼就会判定我们没做功课。正确口径:"复用上游已通的结果回收路径(LAVA 兼容 body → lava_callback.py),我 lab 侧按此回传"。
2. **⚠️ PR3("回调接线/get_meta")重定位**。它不是"补官方欠账、必需的闭环补洞",而是二选一:(a) **不必要**——让 worker 回传 LAVA 兼容 body 即可复用已接线路径;(b) **升级为"原生 pull_labs 协议 body 的服务端解析"增强**——这才是真正无人做过的首创,但工作量大、且要连带处理 `send_kcidb.py` 的 "prepared state" TODO。**当前不建议把 PR3 当必做项。**
3. **worker 回传格式改用 LAVA 兼容 body**(或直接走 `example_pull_lab_lava.py` 的 LAVA 回调路径),**不要用 pull_labs 协议 body**(会被 `lava.Callback` 拒收,缺 `definition` 字段)。
4. **主动对齐上游新变体**:在 PR 描述里说明为何选"纯 pull_labs + tuxrun"而非上游正在推的 "LAVA pull lab(lab_type: lava 无 url)",避免被评"过时/重复"。
5. **排序微调**:既然回调已通、PR3 非必需,更稳的顺序是 **PR1(纯配置,唯一强制交付)先行 + tracking issue + #49 回帖**(与 memo 05 §3 一致);worker/PR2 作为 lab 侧工具后置;PR3 视 reviewer 反馈再定。task 里的 "PR2→PR1→PR3" 应改为 **"#49回帖 + tracking issue → PR1 → (PR2 后置) → PR3 可选"**。

## 7. 本地实跑验证(2026-09-08,调研结论的落地)

✅ **已实现并把"LAVA 兼容 body"路径本地完整闭环**:

1. **worker 改造**(`kernelci-pipeline/tools/riscv_pull_worker.py`):新增 `--lava-callback` 标志 + `lava_body()` 构建器——把 tuxrun 输出翻译成 LAVA 兼容回调体(`status` 2/3、`definition.metadata` 携带 api/storage_config_name、`results.lava` 回放 login-action/kernel-messages、`log` 为 output.yaml 格式);顺带修了一个真 bug:失败批次无 sleep 导致紧循环狂刷 API(实测 31194 次失败)。
2. **解析层验证**:`my-work/tools/verify-lava-body.py` 用真实 PASS/FAIL 日志生成 body,喂给**生产同款解析器** `kernelci.runtime.lava.Callback`,端点调用的全部方法(get_results/get_job_status/get_meta×2/get_log_parser/get_hierarchy/is_infra_error)均通过;pass 日志正确产出 `setup: {login: pass, kernelmsg: pass}` 层级。
3. **端点级验证**:本地跑真实 `lava_callback.py`(uvicorn:8003,`my-work/config/local-callback.toml` 配 token),worker `--lava-callback` 完整跑通:**轮询 → 取任务书 → QEMU boot pass → 打 LAVA body → POST → token 认证 → 解析 → 读节点 → ssh 上传 log/lava-logs/callback_data 三个 artifact → submit_results → 节点 `state: done, result: pass`**(节点 id 6a9fb8bfdb925f2f584f0771,artifact 齐全,device=qemu-riscv64)。
4. **验证途中摸清的三个本地环境事实**(下个会话直接用):token 比对是整个 Authorization 头(`"Token <value>"` 带前缀);`submit_results` 要求 job 节点有 parent(生产里是 kbuild 节点);本地 ssh 存储容器需修 Dockerfile(bullseye-security 已归档,改 archive.debian.org 并删 security 源,`kernelci-api/docker/ssh/Dockerfile` 已改)。
5. **结论兑现**:§4 修正 3("worker 回传改 LAVA 兼容 body")已落地并被真实端点证实;`--lava-callback` 应成为生产默认,PR1 描述即可写"复用上游已通的结果回收路径"。
